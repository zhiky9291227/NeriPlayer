## 一、播放页重设计（方案 A 精神延续：和谐、克制、不动全局）

> GPT 拆解的 8 个问题点，按「影响 × 工程量」排序。核心思想：**播放核心区紧凑化 + 消灭死空间**。

### P0 · 垂直节奏（最大痛点）
- 现状：音频信息 → 播放控制之间略松；歌词 → 底部工具栏之间**巨大死空间**
- 目标：歌曲名 → 歌手 → 进度条 → 播放控制形成一个**紧凑的"播放核心区"**

### P0 · 封面尺寸与圆角
- 尺寸：568px → **500~520px**
- 圆角：40px → **28~32px**
- 封面仍是主视觉，但不做全页唯一中心

### P1 · 音质信息降级
- 现状：「无损 · FLAC · 1004 kbps」视觉权重过高，且"无损"用了主题色
- 方案：缩为「FLAC · 1004 kbps」小字低对比；或并入歌手行「Augustana · FLAC」，点击展开详细参数

### P1 · 播放控制组
- 现状：五按钮横排，中心孤立、两侧被拉开
- 方案：第一层只留 **上一首 / 暂停 / 下一首**；随机+循环降为第二层小控件；缩短间距

### P1 · 歌词预览区（"半成品感"来源）
- 现状：只露一小截暗色文字，像加载失败
- 方案 A：空间不够就干脆隐藏
- 方案 B：真做成预览——两行歌词 + 「查看完整歌词 →」入口

### P2 · 底部五图标信息架构
- 现状：五个图标无文字说明，耳机/音乐卡/音符存在歧义，像"为填满而填满"
- 方案：改成文字抽屉「歌词 · 睡眠定时 · 音频输出 · 队列 · 更多」，或砍到 3~4 个最高频

### P2 · 顶栏简化
- 「正在播放」标题存在感偏高 → 改为「⌄ + ♡ + ⋯」，让封面自然成为中心

### P0 · 底部导航栏 + Mini Player 轻量化（用户点名最明显的视觉负担）

> 核心规则：**内容卡片可以厚，播放控件可以厚，导航必须轻。**
> 问题本质不是"尺寸大一点"，而是 厚 Tab + 厚 Mini Player + 系统导航栏 三层叠加，视觉重心被压到底部。

**现状问题链：**
- Tab 垂直占用大、图标偏大、选中态图标厚、「媒体库」文字明显
- Mini Player 本身已经很厚
- 两者叠加 → `内容 → Mini Player → 厚重 Tab Bar → 系统导航栏` 一整块重区域

**Tab 改造（推荐方案 1：纯图标）：**
- 去掉背景容器，不做圆角 Surface/胶囊（避免"满屏皆卡片"削弱高级感）
- 三个图标：首页 ⌂ / 搜索 ⌕ / 媒体库 ▣
- 选中态 = 图标填充/描边变化 + Accent Color；非选中降低透明度；**不给选中 Tab 大色块**

**备选方案 2（图标+极小文字）：**
- 20-22dp 图标 + 11-12sp 标签，文字绝不成为视觉元素

**Mini Player 同步变薄（关键，不能只改 Tab）：**
- 高度收至 **64-72dp**（封面 32/36dp），Tab 收至 **56-64dp**
- 目标底部结构：`Mini Player（薄条）→ 悬浮 Tab（透明）→ 系统手势区`

**设计原则定案：**
- 卡片负责承载内容（可厚），Tab 负责导航（必须轻：透明、轻、稳定）
- 视觉重量从"底部很重"转为"内容区有重量，导航悬浮于内容之上"
- 与暗色 + 专辑动态色设计天然契合

### 保留项 ⚠️
- **主题色从封面提取**是好评基础（作用于进度条/暂停按钮/标签），保留但**用得更克制**——避免"万物皆染专辑色"

## 二、Bug 清单

### 🔴 BUG-1 · 每日推荐双入口异常（自测发现）
- **现象**：
  1. 从「最近播放」进入每日推荐：先闪现**某个不知名用户的"喜欢的音乐"歌单**（时间短但存在），列表随后正常；且**封面图不显示**
  2. 从「每日推荐」板块进入：封面正常，但**同样闪现陌生人歌单**
- **推测**：请求每日推荐时先返回/先渲染了旧缓存（疑似另一账号的 liked songs 接口残留）→ 缓存 key 或加载顺序问题
- **待查**：每日推荐的 ViewModel 加载链 + 封面字段来源

### 🔴 BUG-2 · 本地下载有隐藏容量上限（酷安用户反馈）
- **现象**：下载 315 首 / 3.2GB 正常，但**退出重进或在本地音乐页刷新后，固定删掉 11 首**，总大小回落到 2.9GB
- **推测**：本地扫描/入库逻辑有数量或体积阈值（如分页加载只取前 N 条、或扫描超时截断），导致超出的文件被判定"无效"而清理
- **待查**：LocalPlaylistRepository / 媒体库扫描逻辑；复现路径 = 下载数量 > ~304 首
- **优先级理由**：涉及**用户数据被删**，属信任级 bug，建议进 v20/v21 必修
